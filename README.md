# MultiRegistrator

Регистратор данных для устройств (регистраторов), работающих по протоколу **Modbus TCP**.
Приложение состоит из двух частей:

* **Сервер** (`run_server.py`) — опрашивает устройства, подсвечивает их состояние,
  непрерывно пишет данные в текстовый архив и предоставляет HTTP API.
* **Клиент** (`run_client.py`) — подключается к серверу по локальной сети, показывает
  список устройств и строит графики (реального времени и статичные за период).

## Возможности

### Сервер
* Кнопка **«Запустить сервер»** / **«Остановить сервер»**.
* Список устройств добавляется через настройки (имя, IP, порт, Modbus ID, карта регистров).
  Карта регистров включает **имя канала**: по Modbus читаются только значения из ячеек
  памяти, поэтому имя канала задаётся вручную (определяется на месте по показаниям) и
  автоматически передаётся всем клиентам.
* Устройству, прошедшему опрос, присваивается **зелёный** цвет, недоступному — **красный**.
  Устройство считается «в сети», если данные по Modbus читаются.
* Автоматический сбор данных и запись в текстовые файлы в папку `archive`
  в корне программы. Для каждого IP — своя папка, для каждых суток — свой файл
  с именем вида `<ip>_<ГГГГ-ММ-ДД>.txt`.
* Деликатная работа с сетью: одно соединение на устройство, объединение соседних
  регистров в минимальное число запросов, отсутствие «шторма» переподключений,
  последовательный опрос всех устройств.
* Встроенный HTTP API для клиентов.

### Клиент
* Подключение к серверу одним действием — адрес берётся из сохранённого списка
  (редактируется в «Настройка → Настройка соединения»), без лишних диалогов.
* Список устройств сервера с индикацией состояния.
* **Единое окно**: выбор устройства открывает график в том же окне, кнопка «← Назад»
  возвращает к списку устройств (без размножения окон).
* Слева панель: выбор периода, **«Выбрать канал данных»**, **«Сформировать график»**,
  кнопка **«Режим реального времени»** (серая — не активна, зелёная — активна),
  **«Автомасштаб»** и блок **«Каналы»**.
* **Сохранение графика в PDF** (текущий вид графика, каналы, период, дата формирования) —
  страница A4 в горизонтальной ориентации, график занимает весь лист; и **печать**
  с окном предварительного просмотра (открывается на весь экран).
* По оси X — время, по оси Y — данные устройства. Верхняя граница оси Y — максимальное
  значение за выбранный период. Максимальный показываемый интервал времени — 24 часа
  плюс 10% запаса для уменьшения/масштабирования графика.
* Фон графика белый; навигация и масштабирование мышью и колёсиком (средства `pyqtgraph`).

## Установка

```powershell
python -m pip install -r requirements.txt
```

Требуется Python 3.10+.

## Запуск

```powershell
# Сервер
python run_server.py

# Клиент
python run_client.py
```

Порядок работы: в сервере добавить устройства через меню «Сервер → Добавить устройство»,
затем нажать «Запустить сервер». После этого пользователи запускают клиент,
подключаются к серверу и открывают графики по устройствам.

## Быстрый старт (без Python)

Готовые exe и бат-файлы-лаунчеры лежат в корне проекта:

* `start_server.bat` — запустить сервер;
* `start_client.bat` — запустить клиент;
* `test_device.bat` — запустить тестовое устройство.

Как всё проверить:

1. Создать демо-данные и добавить тестовое устройство в конфиг:
   `python -m multiregistrator.tools.generate_test_data`.
2. `test_device.bat` — запустить виртуальное устройство (окно не закрывать).
3. `start_server.bat` — запустить сервер и нажать «Запустить сервер».
4. `start_client.bat` — запустить клиент, подключиться и двойным щелчком открыть график.

### Параметры запуска exe

| Программа | Ключ | Действие |
|-----------|------|----------|
| сервер | `--autostart` | сразу запустить опрос и API (без нажатия кнопки) |
| сервер | `--headless` | без GUI, консольный сервер |
| сервер | `--check` | проверить, что API поднимается, и выйти |
| клиент | `--autoconnect` | подключиться к сохранённому серверу сразу |
| клиент | `--server 192.168.1.54:8120` | задать адрес сервера |

### Если клиент пишет «Ошибка подключения»

`WinError 10061 (connection refused)` означает, что по этому адресу никто не слушает.
Проверьте:

* на сервере нажата кнопка **«Запустить сервер»** — API поднимается только после этого
  (либо запустите сервер с ключом `--autostart`);
* IP и порт в клиенте совпадают с настройками сервера (порт по умолчанию `8120`);
* если клиент и сервер на одной машине — используйте `127.0.0.1`;
* брандмауэр серверной машины разрешает входящее соединение на порт `8120`.

## Сборка .exe

```powershell
python -m pip install -r requirements-dev.txt
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Результат — три автономных исполняемых файла в папке `dist` (и копии в корне проекта):

* `dist\MultiRegistratorServer.exe` — сервер;
* `dist\MultiRegistratorClient.exe` — клиент;
* `dist\MultiRegistratorTestDevice.exe` — тестовое устройство (консольное).

Это self-contained сборки (`--onefile --windowed`, у тестового устройства — `--console`),
Python на целевой машине не требуется. Папки `config` и `archive` создаются рядом с `.exe`.

## Тестовое устройство

Для проверки без реального оборудования есть эмулятор: Modbus/TCP-слейв, который
постоянно отдаёт случайную температуру (а также влажность, счётчик и реле).

Запуск — двойным кликом по `test_device.bat`. Устройство активно, пока открыто окно
консоли: закройте его, чтобы остановить. Бат-файл сначала ищет exe в корне проекта,
затем в `dist\`, иначе запускает `test_device.py` через Python.

Параметры (можно передать в бат-файл, например `test_device.bat --port 5020`):

```
--host         адрес прослушивания       (по умолчанию 0.0.0.0)
--port         TCP-порт                  (по умолчанию 5020)
--interval     период обновления, с      (по умолчанию 1.0)
--base-temp    средняя температура       (по умолчанию 25.0)
--amplitude    размах температуры        (по умолчанию 5.0)
--step         шаг случайного блуждания  (по умолчанию 0.4)
--seed         зерно генератора          (для повторяемости)
```

Карта данных для настройки устройства на сервере:

| Функция | Адрес | Тип | Канал | Примечание |
|---------|-------|-----|-------|------------|
| holding | 1 | float32 | `temperature` | °C |
| holding | 3 | uint16 | `humidity` | масштаб (scale) **0.1**, % |
| holding | 4 | uint16 | `counter` | счётчик циклов |
| coil | 1 | bool | `relay` | мигает каждый цикл |

Пример: в сервере добавьте устройство с IP машины, где запущен бат-файл, портом
`5020` и регистрами из таблицы — после «Запустить сервер» оно станет зелёным, а в
`archive\<ip>\` начнут писаться данные.

## Конфигурация

* `config/server_config.json` — настройки API, папка архива, список устройств.
* `config/client_config.json` — адрес сервера и сохранённые соединения.

Обе настройки редактируются из интерфейса и создаются при первом запуске.

## Формат архива

```
archive/
    192.168.1.10/
        192.168.1.10_2026-10-13.txt
        192.168.1.10_2026-10-14.txt
```

Каждый файл — CSV с заголовком:

```
timestamp,analogIn,freqIn,relayStates
2026-10-13 12:00:00.123,30.0,50.0,1
```

## HTTP API сервера

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/health` | проверка доступности |
| GET | `/api/info` | информация о сервере |
| GET | `/api/devices` | устройства и их состояние |
| GET | `/api/devices/{id}` | одно устройство |
| GET | `/api/devices/{id}/latest` | последние считанные значения |
| GET | `/api/devices/{id}/channels` | список каналов |
| GET | `/api/devices/{id}/dates` | доступные даты архива |
| GET | `/api/devices/{id}/data?start=&end=&channels=` | данные за период |

## Структура проекта

```
multiregistrator/
    common/     модели, конфигурация, архив (общие для сервера и клиента)
    server/     Modbus-опрос, планировщик, HTTP API, GUI
    client/     REST-клиент, GUI, графики
    tools/      эмулятор Modbus-устройства и генератор температуры
tests/          тесты на функции всех модулей
run_server.py   запуск сервера
run_client.py   запуск клиента
test_device.py  тестовое устройство (эмулятор Modbus/TCP)
test_device.bat запуск тестового устройства
```

## Тесты

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest
```

Тесты покрывают модели, декодирование регистров, архив, объединение запросов,
Modbus-чтение (в т.ч. интеграционный тест с реальным `pymodbus`-клиентом против
локального Modbus TCP-стенда), планировщик, HTTP API и построение графиков.
